# Operation binding

- Objective owner: current requesting user
- Native owner: generated study-report projection under `.collab/artifacts/**`
- Requested outcome: create a separate Architecture & Algorithms Edition whose
  six Korean PDF volumes explain the project from source truth through runtime,
  turn semantics, effects, durability, extensions, and engineering evolution.
  Decisive algorithms are read from exact source excerpts and related to the
  system guarantees they exist to preserve.
- Success evidence: current implementation, bounded inference, unknowns, and
  recommendations remain distinct; REPL and headless ownership are accurate;
  exact source excerpts support code analysis; algorithms identify inputs,
  state, transition, invariants, complexity, failure boundaries, rationale, and
  improvement seams; every PDF passes source, semantic, pagination, and layout
  validation; representative pages are visually inspected.
- Non-goals: changing the cloned source, asserting unavailable upstream intent,
  running the target's mutating reconstruction checks, or changing reusable
  Loop Architecture and canonical knowledge units.
- Discovery surface: fixed target clone, prior report editions and validation
  records, repository-authored docs, and local engineering/knowledge artifacts
  used as internal decision support.
- Validation: revision and clean-tree checks, exact line-range checks, semantic
  architecture guards, A4 overflow checks, PDF page-count checks, and visual
  sample inspection.
- Material-change signals: target revision change, missing source evidence,
  collapse of REPL and QueryEngine ownership into a false single-engine claim,
  changed six-volume taxonomy, or an algorithm explanation contradicted by its
  cited code.
- Stop conditions: unresolved target revision, source-tree mutation, or a
  decisive explanation that requires inventing missing feature-gated code.

Six-mode resolution: continuation and correction of the active report
objective. The effective primary is `loop`; this is a bounded, single-owner
generation and validation cycle. No parallel source writer or sub-agent
topology is selected. The prior edition remains preserved as history.

The report contract deliberately uses continuous explanatory prose. Code and
algorithms are inserted into an argument—what problem is being solved, what
state changes, why the change preserves an invariant, where that guarantee
ends—instead of being presented as detached evidence cards.

Material-change reassessment: the requester rejected a fixed, repeated report
template. The six repository-derived domains remain the collection boundary,
but their internal page architecture is no longer uniform. Algorithm subjects
use a three-part argument (problem and source, state transition, assurance and
counterexample); language mechanisms may use longer worked-example sequences;
comparisons use tables only when two-dimensional relationships are material;
case narratives and source readings may use their own page rhythm. Page count
and layout are derived from content, not used as an acceptance target.
