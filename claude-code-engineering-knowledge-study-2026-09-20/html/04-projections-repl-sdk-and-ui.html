PROBLEM FRAME01

같은 turn도 소비자마다 다른 모습이 필요하다

REPL, SDK, transcript가 왜 같은 배열을 공유하면 안 되는가?

성립 조건

REPL은 progress와 interactive control을, SDK는 stable event를, transcript는 resume fidelity를 요구한다.

이론 렌즈

projection은 한 source model에서 목적별 view를 파생하며 canonical state와 수명을 구분한다.

코드의 구체화

QueryEngine/query event가 REPL rendering, SDK result, session record로 각각 변환된다.

깨지는 지점

UI 편의를 위해 제거한 event가 transcript에도 사라지거나 SDK normalization이 core state를 mutate하면 drift가 생긴다.

해석surface 차이는 formatting이 아니라 fidelity·latency·durability policy 차이다.

REACT04

render와 commit 사이에 core effect를 두지 않는다

React의 render model이 agent runtime에 주는 제약은 무엇인가?

성립 조건

render는 state의 UI description을 계산하며 다시 실행될 수 있다.

이론 렌즈

React owner 문서는 trigger→render→commit을 구분한다.

코드의 구체화

Ink components는 query state를 화면 요소로 투영하고 hooks가 input/render coordination을 맡는다.

깨지는 지점

render path에서 tool effect나 durable write를 시작하면 재-render와 UI lifecycle이 core semantics를 바꾼다.

해석UI component는 observation을 그려야 하며 effect authority와 canonical transition은 engine boundary에 남아야 한다.

PROGRESS06

보이는 진행과 정식 결과를 구분한다

progress event를 history에 모두 저장해야 하는가?

성립 조건

긴 tool은 사용자가 멈추지 않도록 중간 관찰을 제공해야 한다.

이론 렌즈

projection은 목적에 맞게 detail을 선택하되 source truth를 바꾸지 않는다.

해석progress는 UI/telemetry projection이며 terminal observation과 identity·durability를 분리해야 한다.

GENERATION GUARD07

generation number는 stale continuation을 격리한다

왜 boolean `isRunning`으로 부족한가?

성립 조건

cancel 직후 새 query가 시작되면 이전 async finally가 나중에 실행될 수 있다.

이론 렌즈

generation token은 continuation이 어느 epoch에 속하는지 확인한다.

코드의 구체화

REPL queryGuard가 current generation과 callback/finally의 generation을 비교한다.

깨지는 지점

old finally가 prompt/input state를 복구하면 새 turn의 UI를 덮는다.

해석generation guard는 UI trick이 아니라 overlapping lifecycle의 ownership fence다.

INPUT OWNERSHIP08

prompt field는 단순 문자열 state가 아니다

입력 중 text와 제출된 command의 경계는 어디인가?

interactive surface는 draft text, submitted input, queued command, restored-on-error prompt를 구분해야 한다. 이 상태를 query engine message와 합치면 cancel/resubmit race에서 무엇이 이미 durable한지 모호해진다.

TRANSCRIPT10

CONCLUSION16

화면은 truth를 보여 주지만 truth를 소유하지 않는다

이 권에서 남겨야 할 한 문장은 무엇인가?

좋은 UI 분리는 React 파일을 옮기는 일이 아니라, interactive lifecycle이 core history와 effect authority를 바꾸지 못하게 하는 일이다.

REPL과 SDK는 같은 conversation engine의 소비자여야 하지만 동일한 projection일 필요는 없다. 차이는 명시적이고 testable해야 한다.
