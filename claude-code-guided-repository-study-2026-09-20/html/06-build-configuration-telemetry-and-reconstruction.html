큰 파일은 책임 분포를 찾는 지도이지 자동 분해 명령이 아니다

query.ts, main.tsx, REPL.tsx, claude.ts는 서로 다른 변화가 한 지점에 모였다는 신호다.

각 큰 파일에서 import cluster, state owner, error handling, consumer를 보면 후보 seam이 나온다. query는 turn protocol, main은 composition, REPL은 projection controller, claude.ts는 provider adapter로 중심 성격도 다르다.

모두 같은 “service extraction” 처방을 쓰면 의미가 나빠질 수 있다. state machine은 transition owner를, composition은 dependency graph를, adapter는 normalization contract를 중심으로 나눠야 한다.

분해 전에는 characterization trace를 만든다. happy path output뿐 아니라 cancellation, permission denial, resume, cache behavior를 포함해야 한다.

코드 뒤에서 작동하는 언어·런타임 메커니즘

문법 이름을 외우기보다, 런타임이 실제로 무엇을 저장하고 언제 제어를 넘기는지와 이 프로젝트가 그것을 어떤 책임에 사용하는지를 함께 본다.

compile-time intrinsic

언어가 제공하는 것
bundler가 표현을 상수로 치환하고 도달 불가능 branch를 제거한다.
이 저장소가 쓰는 방식
feature()와 MACRO가 배포 variant를 만든다.
놓치기 쉬운 함정
runtime flag처럼 생각하면 누락 모듈을 나중에 켤 수 있다고 오해한다.

dead-code elimination

언어가 제공하는 것
정적으로 false인 branch와 참조를 bundle에서 제거한다.
이 저장소가 쓰는 방식
내부 전용 기능을 외부 npm artifact에서 제외한다.
놓치기 쉬운 함정
복원 source의 dangling import만으로 제거된 구현을 재구성할 수 없다.

ESM module graph

언어가 제공하는 것
static import가 bundle resolution과 side-effect order를 결정한다.
이 저장소가 쓰는 방식
entrypoint와 provider/service dependency를 구성한다.
놓치기 쉬운 함정
false branch 안 import도 도구에 따라 resolution될 수 있어 stub이 필요해진다.

configuration precedence

언어가 제공하는 것
여러 source의 value를 정해진 우선순위와 validation으로 합친다.
이 저장소가 쓰는 방식
default/user/project/managed 설정이 effective behavior를 만든다.
놓치기 쉬운 함정
object spread만 남기면 값의 source와 override 불가 이유가 사라진다.

idempotent migration

언어가 제공하는 것
같은 변환을 반복해도 한 번 적용한 것과 같은 durable state를 만든다.
이 저장소가 쓰는 방식
model alias와 설정 key의 역사적 의미를 새 버전으로 옮긴다.
놓치기 쉬운 함정
부분 write와 복합 설정 분해가 원자적이지 않으면 중간 상태가 남는다.

batched telemetry exporter

언어가 제공하는 것
event를 buffer·batch·retry하고 실패 데이터를 disk에 보존한다.
이 저장소가 쓰는 방식
운영 분석을 network 장애 뒤에도 전달한다.
놓치기 쉬운 함정
신뢰성이 높아질수록 privacy·retention surface도 넓어진다.
