SNAPSHOT01

규모가 아니라 분포를 먼저 본다

라인 수는 난도를 말해 주지 않는다. 어떤 책임이 어디에 몰려 있고, 어떤 파일이 많은 경계를 동시에 연결하는지가 더 중요하다.

증거 등급
코드 위치와 분포 수치는 고정 커밋의 정적 분석 결과다. 제품 의도·운영 동작·현재 버전에 대한 설명은 별도 검증 없이는 추정으로 취급한다. 저장소 자체가 “decompiled source”라고 밝히며 완전 재빌드 불가와 누락 모듈을 명시한다.
SCC 해석
거대 strongly connected component는 “모든 코드가 나쁘다”는 판정이 아니다. barrel/export, UI와 runtime의 상호 참조, 복원 과정의 평탄화가 함께 만든 변경 위험 신호다.

CYCLES08

거대 순환 연결 요소를 어떻게 읽을까

정적 상대 import 그래프에서 8개 SCC가 보이며, 가장 큰 SCC는 1,136파일이다. 이는 변경 전파와 격리 난도를 보여 주는 관찰이지 품질 점수는 아니다.

원인 후보

barrel과 facade

편리한 re-export가 내부 모듈로 다시 들어오면 cycle을 만든다.

원인 후보

UI/runtime 교차

Tool 계약이 React node를 포함하고 runtime이 UI 표현을 참조한다.

원인 후보

global state

AppState·bootstrap singleton·settings가 횡단 관심사를 묶는다.

원인 후보

복원 평탄화

원 모노레포 경계가 단일 src로 복원되며 package boundary가 사라졌을 수 있다.

분석 실습
SCC를 즉시 제거하려 하지 말고, 한 tool vertical slice에서 type-only edge, UI edge, runtime edge를 색으로 구분한다. 잘라야 할 seam이 보일 때만 refactor 가설을 세운다.
