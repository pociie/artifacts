BATCHING NUANCE10

자동 배칭을 16ms 타이머로 단정하지 않기

참고 영상은 빠른 SSE chunk를 React가 묶어 flicker를 줄인다는 직관을 제공한다. 다만 정확한 timing은 React scheduler, Ink renderer, stdout flush 구현과 버전에 달려 있다.

확인 가능

state update batching

여러 update가 하나의 render/commit으로 합쳐질 수 있다.

미확인

고정 16ms

항상 60fps cadence라는 보장은 소스/측정 없이 단정하지 않는다.

host cost

stdout write

React render보다 ANSI diff와 terminal emulator가 병목일 수 있다.

측정

frame trace

chunk time, render count, bytes written을 함께 기록한다.

교육 포인트
좋은 설명 모델은 원리를 잡게 하지만, 성능 수치·스케줄 보장으로 확장될 때는 구현과 계측이 필요하다.

TESTING15

UI를 세 층으로 테스트한다

terminal snapshot 하나에 모든 의미를 맡기면 fragile하다.

  1. pure transition — key/mode/input으로 guard 결과를 table test한다.
  2. component render — state별 element/output을 Ink test renderer로 확인한다.
  3. host integration — pseudo-TTY에서 ANSI, resize, Ctrl+C, scrollback을 확인한다.
  4. cross-boundary — mock async generator로 streaming→completed 전이를 검증한다.
  5. accessibility/operability — color 없이도 permission/error가 구분되는지 본다.
실습 · frame probe

10ms마다 100개 chunk를 보내고 실제 stdout write 횟수·byte·최종 frame을 측정한다.
