DEFAULTS03

buildTool 기본값을 비판적으로 읽기

builder는 누락 메서드를 채워 모든 tool을 완전한 계약처럼 보이게 한다. 그러나 각 기본값의 안전 의미는 같지 않다.

기본값값해석
isConcurrencySafefalse보수적 직렬화 — fail closed
isReadOnlyfalsewrite 가능성 가정 — 보수적
isDestructivefalse파괴성 표시에는 비보수적; 별도 permission이 중요
checkPermissionsallow + inputtool-specific check 생략, general permission system에 의존
classifier input빈 문자열security-relevant tool은 반드시 override 필요
isEnabledtrue등록되면 기본 노출 가능
리뷰 질문
“default가 있다”가 “안전하다”는 뜻이 아니다. 새 tool template은 effect classification·classifier·permission override를 checklist로 강제해야 한다.

SECURITY REVIEW15

tool 하나를 리뷰하는 질문 순서

설명보다 데이터·권한·효과 경계를 먼저 본다.

  1. enumerate — 입력 필드, 파생 path, credential, network target을 열거한다.
  2. canonicalize — parse·normalize 후 검사와 실행이 같은 값을 쓰는지 본다.
  3. classify — read/write/destructive/open-world/concurrency 속성을 input별로 판정한다.
  4. mediate — general rule, tool-specific rule, hook, human prompt의 순서와 precedence를 본다.
  5. contain — sandbox/timeout/output limit/abort를 확인한다.
  6. observe — 최소 telemetry와 audit correlation을 본다.
  7. settle — partial effect, error, cancellation 뒤 state를 본다.
실습 · FileWrite threat model

path traversal, symlink race, overwrite, permission cache, abort-after-open 사례를 STRIDE식으로 정리한다.

완료 증거: attack → control → residual risk 표
