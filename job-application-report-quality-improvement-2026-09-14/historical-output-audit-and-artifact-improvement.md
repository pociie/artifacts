# 자기소개서 보고서 아티팩트 품질 개선 기록

## 결론

세 결과물의 품질 차이는 PDF 렌더링 성공 여부보다 **문항별 작성 목적을
구분하는 장치, 후보 간 실질적 차이를 검토하는 장치, 내부 운영 언어를
독자 언어와 분리하는 장치, 편집 보고서의 정보 위계를 검토하는 장치**가
현행 아티팩트에 충분히 강제되지 않았기 때문에 발생했다. 특히 최대
글자수에 대한 고정 채움률과 모든 문항에 동일한 깊이 신호를 요구한 규칙은
근거를 보강하라는 의도와 달리 공통 마무리 문단을 붙이는 방향으로
사용되었다.

이번 개선은 글자수 채움률을 제거하고, 문항군별 의미 구조와 독립 의미
검토를 도입하며, 제출용 답안 투영을 정식 스키마와 검증 대상으로 만든다.
자동 유사도 값은 품질 점수가 아니라 검토가 필요한 위치를 찾는 신호로만
사용한다.

## 결과물별 진단

### Coremotion 5세트 PDF

기술적으로는 PDF, 검색 가능한 본문, 페이지와 오버플로 검사가 완료되어
기존 검증을 통과했다. 그러나 네 문항 중 세 문항에서 같은 긴 마무리
문장이 다섯 후보에 반복되었고, 답안 생성 코드가 문항별 공통 suffix를
모든 후보에 덧붙였다. 개선된 검사기의 문항별 최대 pairwise 5-token
n-gram 유사도는 0.110~0.325였고, 프로세스 개선 문항은 0.325로 나타났다.
이는 후보 제목은 달라도 실제 주장·근거 사용·결론이 충분히 달라지지
않았음을 보여준다.

보고서는 카드 컨테이너를 반복해 본문·평가·주의사항의 중요도가 비슷하게
보였고, 영문 기준 ID와 publication validation 같은 내부 표현을 독자용
레이블로 노출했다. 공식 확인이 되지 않은 예시 도메인을 공고 근거처럼
보여 준 점도 회사 분석의 신뢰도를 낮췄다.

### Finebridge 제출용 HTML

사용자가 지정한 `application-ready-self-introduction-set-2.html`은 전문가
검토 보고서가 아니라 제출용 답안만 남긴 투영이다. 따라서 기업 분석,
평가, 면접 준비가 없다는 이유만으로 v6 보고서보다 품질이 낮다고 판단할
수 없다. 실제 검토 보고서는 별도의 `self-introduction-set-2.html`이고,
요청 자체가 2세트 HTML이었으므로 5세트 PDF가 아닌 것도 요청 불이행이
아니다.

두 답안 후보의 문장 중복은 매우 낮아 표현 면에서는 Coremotion과
Nextwave보다 낫다. 문항별 최대 pairwise 5-token n-gram 유사도는
0~0.037이었고 반복 긴 문장은 없었다. 다만 기존 결과 스키마가 제출용
투영을 독립 산출물 역할로 표현하지 못해 `source_document`로 잘못
분류했고, 답안 본문이
검토 완료된 결과와 동일한지 또는 검토 메타데이터가 섞이지 않았는지
검증할 수 없었다. 실제 검토 보고서의 시각 구조도 패널과 카드가 많은
일반 웹 페이지에 가까워, 전문가 편집 보고서의 비교 위계는 약했다.

### Nextwave 5세트 PDF

기존 형식 검사를 통과했지만 모든 후보에 같은 내용 깊이 보강 문단을
붙였다. 입사 후 기여 문항의 최대 pairwise 5-token n-gram 유사도는
0.445로 가장 높았고, 여러 긴 문장이 다섯 후보에 그대로 반복되었다. 이
경우 높은 글자수 활용도는 내용의 충분함보다 공통 문단의 길이를 반영했다.

보고서에는 content-depth 게이트, 깊이 신호, 작업용 상한, 공개 근거 같은
제작 과정 언어와 원시 영문 평가 ID가 노출되었다. 넓은 가로 페이지에 작은
글자와 빈 공간이 많아 페이지 수에 비해 정보 밀도와 읽기 흐름도 좋지
않았다. 렌더링 검사는 이 문제를 구조적 오류로 보지 않았기 때문에 통과했다.

### v6 기준 보고서

v6는 같은 크기의 가로형 PDF 안에서 표·정렬 행·구분선·여백을 이용해
답안, 점수 의미, 전문가 검토, 면접 확인을 한 흐름으로 묶었다. 원시 기준
ID 대신 독자 언어를 사용했고, 래스터 자산은 관계를 설명할 때만 사용하며
자기소개서 본문은 검색 가능한 텍스트로 유지했다. 세 문항의 후보 간
5-token n-gram 평균 유사도는 약 0.003, 0.003, 0.012로 매우 낮았다.
확인된 지원자 가치 문장처럼 의미상 필요한 반복만 일부 남았다.

v6도 고정 금칙어와 페이지 수 같은 보고서별 규칙을 재사용 계약으로
일반화할 수는 없다. 이번 개선은 v6의 정보 위계와 답안 차별성은 보존하되,
특정 파일명·버전·회사·페이지 수를 검사기에 하드코딩하지 않는다.

| --- | --- | --- | --- |

## 개선된 평가 운영

평가 순서는 다음과 같다.

1. **사실·귀속 적격성**: 문항, 공고, 지원자 진술, 프로젝트 역할과 결과
   한계를 먼저 확인한다. 실패하면 점수를 계산하지 않는다.
2. **문항군 적합성**: 해당 문항의 독자 질문, 필수 전개 역할, 하나의 중심
   생각, 결론 기능이 실제 답안에서 관찰되는지 독립 검토한다.
3. **목소리와 공개 언어**: 가치관이 지원자의 선택과 결과로 드러나는지,
   답안이 보고서 생성·검증·점수 절차를 설명하지 않는지 확인한다.
4. **후보 차별성**: 주장, 근거 사용, 판단 원칙, 독자 요지, 결론 중 무엇이
   다른지 설명하고, 자동 반복도 신호가 가리키는 문장을 검토한다.
5. **비교 점수**: 앞선 비보상 조건을 통과한 후보만 문항 적합성, 직무
   맥락, 지원자 관점, 근거 인과, 표현 응집력, 면접 방어 가능성으로 비교한다.
6. **편집·출판 품질**: 실제 렌더에서 정보 위계, 정렬 비교, 페이지 경제성,
   공개 레이블, 검색 가능한 본문, 오버플로와 출처 노출을 함께 확인한다.

유사도 0.18은 자동 탈락선이 아니라 독립 검토를 반드시 남기는 기본
신호값이다. 회사명, 공식 제품명, 사용자가 직접 확인한 가치 문장처럼
반복이 필요한 경우에는 근거와 이유를 기록할 수 있다. 반대로 유사도가
낮더라도 문항 목적이 틀리거나 내부 언어가 누수되면 통과할 수 없다.

## 재사용 시 필요한 실행 자료

새 실행은 회사명과 직무명만으로 시작하지 않는다. 정확한 공고 원문과
관찰일, 모든 문항과 문항별 최소·최대 글자수, 원하는 후보 수와 출력 형식,
지원자가 확인한 경험·가치·역할·성과 한계, 프로젝트 근거, 보고서 독자와
디자인 요구가 필요하다. 문항마다 분류한 문항군, 독자에게 남길 요지,
전개 역할, 목소리 근거, 결론 기능을 request에 기록한 뒤 작성해야 한다.

5세트 PDF 프로필을 선택하면 PDF·원본 HTML·텍스트 추출·제출용 답안
투영을 함께 만들고, request/result 검사, 프로필 검사, 답안 투영 검사,
쓰기 품질 의미 검토, 실제 PDF 렌더 검사를 모두 통과해야 한다. 한 검사의
통과를 다른 검사나 높은 점수로 대신할 수 없다.

## 외부 근거

- Purdue OWL의 수사 상황과 장르 분석은 독자·목적·맥락과 반복되는 수사적
  움직임을 함께 보도록 한다.
- Harvard FAS의 면접 지침은 상황-행동-결과를 행동 질문에 사용하는 방식과
  결론·학습을 고용주와 연결하는 방식을 설명한다.
- UNC Writing Center는 한 문단을 하나의 중심 생각으로 통일하고, 예시가
  중심 생각을 어떻게 뒷받침하는지 설명하도록 권한다. 명료한 주체와 동사,
  불필요한 장황함 제거도 강조한다.
- GOV.UK Design System과 W3C 지침은 읽기 폭, 간격, 진짜 표 데이터,
  헤더 관계, 색상 외 단서 같은 편집·접근성 판단 근거를 제공한다.

상세 URL과 적용 한계는 재사용 Skill의 두 참고 문서에 보존했다. 외부
자료는 작성·편집 방법의 근거일 뿐 채용 판단이나 지원자 사실의 권위가 아니다.
